- 请求日志新增尝试与重试次数、使用账号数和逐次记录；验证码失败、同账号重试及换号保存在同一请求下，详情展示账号、阶段、耗时、错误、命中规则与后续处理。旧日志显示次数未记录。

- 账号保护只保留「自定义规则」一个设置入口；旧健康接口和错误统计入口统一调用同一策略，移除旧阈值自动停用逻辑，并防止日志失败导致同次生成失败重复计数。
- 修复普通 Chrome／Edge 从 `/login` 登录后停在 `/login#/accounts` 时无法检测扩展；补齐管理页面入口，连接超时提示区分站点权限与版本不兼容，不再将未连接误报为旧扩展。
- 新增 Flow 自定义错误规则，支持 LIMIT、DEACTIVE、RETRY、DISABLE、DELAY 与 s/m/h 时间；规则可修改、删除或清空，保存后生效。额度耗尽可冷却并换号，连续失败触发可配置保护；未知提交结果与已受理任务不重复生成。
- 设置页改为顶部分类、紧凑横向表单与独立规则编辑区；账号页显示生成保护原因、恢复时间及解除入口。默认调度优先低负载和最久未使用账号，轮询保持可用账号顺序。
- Windows 扩展登录可一键打开本机 Chrome／Edge，默认使用临时无痕窗口，无需指纹浏览器；缺少无痕权限时明确提示，已有其他无痕窗口时保留其会话并提示关闭后再开始。
- 已有 Cloak 账号再次通过 Cookie JSON、Profile JSON 或扩展登录时，更新原账号登录态，保留原账号编号、固定代理、指纹、站点数据及用户设置。新登录态在私有副本中验证一次，失败回滚；后台导入正确统计为“更新”。
- 扩展登录提交超时或服务器拒绝后直接显示错误，不再自动重复提交；后台失败任务仅在手动点击重试时执行。续接旧 Profile 时先应用本次已验证 Cookie，再校验一次，不先尝试失效登录态。
- 账号页的 JSON 导入兼容包含 `cookies` 和 `email` 的外部账号资料，支持单账号和混合数组；在固定代理上核验真实身份、Flow 会话和额度后保存。新导入 Profile 保留会话 Cookie，源 `sid`、项目和会员字段不作为登录验证依据。
- 创作台允许直接删除或批量清理等待确认、待下载和下载失败卡片；保留服务器原任务与收据，刷新后不再恢复已清理卡片。本机存储无法保存删除结果时保留卡片并提示重试。
- 扩展登录重试可续接进程中断留下的未完成 Profile，核验原身份、seed、启动配置和代理绑定后继续验证；保留 Profile 的原代理优先于新分配出口，任务内加密保存修正后的绑定。
- 自动刷新区分 HTTP 有效性检查与浏览器续期：到期时同步最新 Cookie 到原 Profile，并在原固定代理上正常打开、验证和关闭；普通 403 不再直接判为掉登录，曾验证账号有两次限量恢复重试后才要求人工登录。
- 扩展登录资料先加密持久入队，再释放当前登录窗口；后台成功、失败和重试状态保留在账号页，服务重启不再静默丢失已接受的账号。
- 扩展登录、Cloak 登录和 Profile 导入在身份及冷启动验证通过后保存账号，工作区按实际创作需要准备；项目接口暂时失败不会再把已验证的账号标记为迁移失败或关闭自动刷新。新登录账号默认开启自动刷新。
- Flow 项目列表为空时正常创建首个项目；项目池扩容遇到临时失败时继续使用已保存项目，保留账号身份和固定代理校验。
- 账号列表直接调整自动刷新、创作能力和备注；“编辑”一次打开完整配置面板，全部字段展开，无需切换标签。

## 1.3.0 — 2026-10-22

### 新增

- Windows 增加独立桌面应用窗口，采用 WinForms + WebView2；桌面快捷方式启动 `Lay4Flow.Desktop.exe`，在窗口内使用本地创作工作台。
- 全局增加「更新日志」抽屉，显示当前版本、发布日期和逐版变更；侧栏、用户菜单和桌面菜单均可打开，登录前也可查看。
- 桌面菜单提供「更新日志」和「检查更新」入口，检查 GitHub 版本由用户手动触发。

### 运行与升级

- 桌面包自带 .NET 运行时，需 Docker Desktop 与 Microsoft Edge WebView2 Runtime；后端继续使用 Docker，账号资料与配置沿用安装目录。
- 关闭桌面窗口保留后台生成任务。安装器仍保留已有目录和数据，同款 TkCRM 图标用于安装器和桌面应用。

## 1.2.1 — 2026-10-22

### 修复

- 修复 Windows 安装时已有同名 Docker 项目导致的失败；EXE 自动为新安装选择独立项目和可用端口，原实例和数据保持原位。
- 安装失败保留完整 PowerShell/Docker 日志，直接显示具体原因和日志位置。
- 安装器沿用 TkCRM 头像图标，修复中文目录检查并阻止将系统目录作为安装目录。

### 升级

- 已有安装的数据和配置保留。安装包依赖 Docker Desktop；安装日志位于 `%TEMP%\lay4flow-remote-install.log`。

## 1.2.0 — 2026-10-21

### 新增

- Windows 安装 EXE、安装包图标与桌面启动/更新快捷方式统一使用 TkCRM 的同款头像图标。
- 提供 Windows 一键安装包：解压后双击 `install.cmd`，自动检查 Docker Desktop、初始化示例配置、启动服务并创建桌面启动/更新快捷方式；已有 `data/`、`tmp/`、`.env` 和 `config/setting.toml` 会保留。
- 提供 Docker 在线更新脚本，下载运行包后先校验 SHA-256，再隔离构建、健康检查和版本确认；失败自动恢复上一镜像，支持显式回滚。
- 设置页新增版本与更新记录卡片，可查看本地变更、打开 Windows/Docker 指引并手动查询 GitHub 发布页。查询失败不影响创作任务。

### 升级

- Windows：需要 Docker Desktop for Windows（WSL 2 引擎）和 Compose v2；单实例更新会短暂重启服务，浏览器重新打开后继续使用。
- Docker：沿用 `lay4flow-remote` Compose 项目、绑定目录和端口；升级前建议备份 `data/` 与 `config/setting.toml`。脚本不会执行 `down -v`、卷删除或 prune。

### 已知限制

- 当前 Windows 包是 Docker Desktop 启动器，不包含 Docker 引擎本身；未安装 Docker Desktop 时安装器会给出官方下载入口。
- Docker 单实例切换存在短暂中断，不宣称零停机；正在执行的上游请求由应用按现有任务恢复策略处理。

## 1.1.0 — 2026-10-21

此节记录首个公开安装包之前的源码版本行为。

- 创作工作台支持图片和视频每批生成 1–20 份。提交后立即进入服务端后台队列，可以继续编辑、提交下一批、切换页面或刷新；每份任务独立显示排队、生成、完成和失败状态。
- Vids 批量任务为每份作品保留独立幂等键和原收据。服务重启不会自动重复发送可能已经计费的请求，待确认收据继续保留。
- 账号增加「生成提交出口」策略：账号固定代理或代理池分配。池分配优先选择较久未使用的可用出口，再比较处理中数量；成功率保留为健康统计，一份生成任务全程保持同一出口。
- 代理池增加连续失败熔断和周期探针：连续 3 次传输失败进入冷却，冷却时间逐步增加到最多 5 分钟；后台每 30 秒探测到期出口，探测成功后恢复。403、429、额度和内容错误不会被计为代理故障，也不会因为代理波动累计账号错误。
- 修复 SOCKS 代理握手错误分类。`ProxyError` 及 curl 5/7/97 等错误保留安全的连接阶段信息，SOCKS 请求不再错误回退到不支持 SOCKS 的 urllib 通道；生成重试会重新获取验证码并保持账号出口策略。
- 设置页的「最大尝试次数（含首次）」现在严格控制 Flow 生成总尝试次数，验证码异常不再偷偷提升到其他默认上限。图片生成失败记录保存每次尝试、验证码状态、耗时和错误原因，工作台请求详情和任务卡均可查看。
- 视频放大区分验证码获取失败与实际提交失败，在服务端日志和进度文本中显示尝试次数、提交次数及原因；放大失败保留原视频。图片放大失败同样保留原图。
- 管理后台会话默认保持 30 天，容器重启后继续有效；退出和修改密码立即撤销。业务接口的 401 不再误判为管理会话失效，登录首屏竞态也已修复。
- Cloak 未完成登录在服务关闭或超时后保留临时账号、原 Profile 和固定出口，可继续登录；显式取消仍清理临时账号。Google `gmail.com` / `googlemail.com` 别名在 Profile 校验、探针、刷新和导入去重中按同一身份处理，其他域名保持精确匹配。
