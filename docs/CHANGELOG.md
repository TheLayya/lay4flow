# 更新记录

## 1.5.1 — 2026-10-22

### 修复

- Cloak 登录、凭据刷新和 Profile 迁移改用 Google Flow 当前的身份与额度 RPC，不再请求已停用的 Labs CSRF、NextAuth session 或旧 ST→AT 入口。
- Gmail `gmail.com` / `googlemail.com` 别名继续按同一 Google 身份校验；其他邮箱保持严格匹配。
- 登录失败显示 Flow bootstrap、身份、额度和项目阶段，保留可重试状态，不泄露 Cookie、AT 或代理凭据。
- Profile 刷新保存浏览器会话和额度，不伪造旧 AT；生成调度暂时跳过尚未接入新版生成 RPC 的 Cloak 账号。
- Docker/Linux 与 Windows 原生 Profile 迁移保留固定代理、Profile seed、身份和冷启动校验；项目写入增加账号/Profile/代理绑定的原子校验。

### 验证与限制

- 通过 1381 项后端测试、前端测试、离线 smoke，以及原生登录和 Profile 迁移 E2E。
- 新版 Flow 身份、额度和项目列表 RPC 已完成现场只读验证，用户手动刷新成功；真实内容生成仍待新版接口适配。
- Windows 包自带 Python、Cloak 与桌面运行时，无需用户安装 Docker 或开发工具；提供安装 EXE、ZIP、runtime 与 SHA256，安装器当前未做 Authenticode 签名。
- 已在本机独立目录验证安装与原生服务；全新无 Docker Windows 环境及旧版桌面入口更新验收保留待验状态，GitHub 资产以草稿候选保存。

## 1.5.0 — 2026-10-22

### Windows 原生安装

- Windows 安装包自带 Python 后台、依赖和 Cloak 浏览器，安装与启动不再依赖 Docker Desktop、Python 或 Node。
- 管理桌面直接启动本机后台服务；Cloak 登录打开本机原生浏览器窗口，省去网页画面转发。
- 系统代理自动发现使用本机地址与实际端口，兼容系统代理/PAC 和 TUN。
- 原生后台支持后台任务、正常关闭和数据保留；更新安装先备份，验证失败恢复原运行文件与资料。

## 1.4.0 — 2026-10-22

### 桌面体验

- 首次打开默认最大化，按显示器工作区和 DPI 限制最小窗口，记住窗口位置与状态。
- 工作台的描述、参数和素材分区切换，数量与提交按钮保持可见；设置页按分区切换。总览、账号和代理池适配桌面视口，搜索与分页固定可见，长列表仅在表格内部滚动。
- 左下角版本号统一作为更新入口；更新日志内检查和执行更新，移除独立 update 桌面快捷方式。
- 桌面更新下载并校验完整 Windows 安装包，显示过程，服务更新后自动重启桌面；失败保留日志并恢复原桌面文件。

### Windows 网络

- 启动时自动读取系统代理/PAC，系统代理未启用时识别代理软件实际监听端口，避免写死端口或要求 TUN。
- 支持宿主代理作为账号 SOCKS5 的前置通路，账号最终出口和 Profile 固定绑定保持不变。
- 可通过 `LAY4FLOW_HOST_PROXY_MODE=auto/direct/manual` 选择自动、直连或手动网络；检测结果保存于私有 `data/host-network.json`。
- Cloak、Flow、Vids、代理检测和媒体下载复用相同的宿主前置链；工坊状态显示容器到宿主代理端口的实际连通结果。
- Profile 导入失败显示 Google 登录入口、续签、授权回调、会话或额度校验的具体阶段，原资料保留并支持重试。

## 1.2.0 — 2026-10-21

### 新增

- Windows 安装 EXE、安装包图标与桌面启动/更新快捷方式统一使用 TkCRM 的同款头像图标。
- 提供 Windows 一键安装包：解压后双击 `install.cmd`，自动检查 Docker Desktop、初始化示例配置、启动服务并创建桌面启动/更新快捷方式；已有 `data/`、`tmp/`、`.env` 和 `config/setting.toml` 会保留。
- 提供 Docker 在线更新脚本，下载运行包后先校验 SHA-256，再隔离构建、健康检查和版本确认；失败自动恢复上一镜像，支持显式回滚。
- 设置页新增版本与更新记录卡片，可查看本地变更、打开 Windows/Docker 指引并手动查询 GitHub 发布页。查询失败不影响创作任务。

### 升级

- Windows：需要 Docker Desktop for Windows（WSL 2 引擎）和 Compose v2；单实例更新会短暂重启服务，浏览器重新打开后继续使用。
- Docker：沿用 `lay4flow-remote` Compose 项目、绑定目录和端口；升级前建议备份 `data/` 与 `config/setting.toml`。脚本不会执行 `down -v`、卷删除或 prune。

### 已知限制

- 当前 Windows 包是 Docker Desktop 启动器，不包含 Docker 引擎本身；未安装 Docker Desktop 时安装器会给出官方下载入口。
- Docker 单实例切换存在短暂中断，不宣称零停机；正在执行的上游请求由应用按现有任务恢复策略处理。

## 1.1.0 — 2026-10-21

此节记录首个公开安装包之前的源码版本行为。

- 创作工作台支持图片和视频每批生成 1–20 份。提交后立即进入服务端后台队列，可以继续编辑、提交下一批、切换页面或刷新；每份任务独立显示排队、生成、完成和失败状态。
- Vids 批量任务为每份作品保留独立幂等键和原收据。服务重启不会自动重复发送可能已经计费的请求，待确认收据继续保留。
- 账号增加「生成提交出口」策略：账号固定代理或代理池分配。池分配优先选择较久未使用的可用出口，再比较处理中数量；成功率保留为健康统计，一份生成任务全程保持同一出口。
- 代理池增加连续失败熔断和周期探针：连续 3 次传输失败进入冷却，冷却时间逐步增加到最多 5 分钟；后台每 30 秒探测到期出口，探测成功后恢复。403、429、额度和内容错误不会被计为代理故障，也不会因为代理波动累计账号错误。
- 修复 SOCKS 代理握手错误分类。`ProxyError` 及 curl 5/7/97 等错误保留安全的连接阶段信息，SOCKS 请求不再错误回退到不支持 SOCKS 的 urllib 通道；生成重试会重新获取验证码并保持账号出口策略。
- 设置页的「最大尝试次数（含首次）」现在严格控制 Flow 生成总尝试次数，验证码异常不再偷偷提升到其他默认上限。图片生成失败记录保存每次尝试、验证码状态、耗时和错误原因，工作台请求详情和任务卡均可查看。
- 视频放大区分验证码获取失败与实际提交失败，在服务端日志和进度文本中显示尝试次数、提交次数及原因；放大失败保留原视频。图片放大失败同样保留原图。
- 管理后台会话默认保持 30 天，容器重启后继续有效；退出和修改密码立即撤销。业务接口的 401 不再误判为管理会话失效，登录首屏竞态也已修复。
- Cloak 未完成登录在服务关闭或超时后保留临时账号、原 Profile 和固定出口，可继续登录；显式取消仍清理临时账号。Google `gmail.com` / `googlemail.com` 别名在 Profile 校验、探针、刷新和导入去重中按同一身份处理，其他域名保持精确匹配。

验证使用合成凭据和模拟上游，覆盖后端全量回归、前端测试、批量生成浏览器场景、代理策略专项、重试设置链路和 Docker smoke；实际账号成功率需在运行环境单独观察。真实账号、运行数据库、Profile 与密钥不进入仓库。
