# VIDS-STARTUP-ISOLATION

- State: done
- Owner: Codex
- Requirement: restore Vids after all saved accounts show startup_timeout and quota/reconnect return Vids runtime unavailable.
- Finding: application startup wraps the whole saved-account restore in a 60-second timeout; runtime publishes only after every account bootstrap finishes. Cancellation clears the entire pool, while reconnect excludes startup_timeout from recoverable runtime states.
- Profiles: Vids runtime lifecycle, application startup/shutdown, explicit reconnect, admin state and account UI.
- Acceptance: slow/unreachable saved sessions are isolated and bounded; healthy sessions become available independently; Flow/console startup does not wait for upstream Vids; configured binding and original receipt/media affinity survive partial failures; explicit single-account reconnect can recover a failed startup; status distinguishes restoring/timeouts from identity mismatches. Cancellation drains opened clients, runtime locks and background work before shutdown; no late publication and no paid replay.
- Preserve: account identity/fixed proxy/Profile/cache semantics, per-account protection and manual disable, no extra blank documents or automatic generation retries. Public artifacts exclude configs/credentials/profiles/DBs/media/diagnostics.
- Verification: synthetic delayed/failing gateways and real temporary storage only; focused runtime/reconnect/admin tests, frontend tests and browser states, independent audit, required `python -X utf8 scripts/check.py` and `npm.cmd --prefix frontend test`, current frontend build and healthy current Docker delivery. Any live read-only provider check is recorded separately from local acceptance; no paid generation.
